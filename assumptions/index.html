Assumptions

This document lists the current assumptions behind Debug GYM and how they can be checked with learners in Week 2. All assumptions remain Open until they are validated.

ASM-01 — Realistic debugging context

Assumption: Learners want debugging practice that resembles working in an existing codebase.

  • Status: Open
  • Validation: Ask learners to compare a single-snippet task with a small, multi-file task.
  • Observe: Which format better supports their goals, and why?

ASM-02 — Approachability of repository-level tasks

Assumption: Repository-level debugging tasks can be approachable for learners.

  • Status: Open
  • Validation: Observe learners as they start and attempt to complete a small repository-level task.
  • Observe: Where do they need help, get stuck, or stop?

ASM-03 — Added value over existing kata

Assumption: Repository-level debugging practice offers value that existing kata do not.

  • Status: Open
  • Validation: Ask learners to compare a Debug GYM repository-level task with a kata they have used before.
  • Observe: What value, if any, do they identify in the repository-level task?

ASM-04 — Feedback on the debugging process

Assumption: Learners value feedback on how they investigate a bug.

  • Status: Open
  • Validation: Show learners investigation feedback in a Week 2 prototype.
  • Observe: Whether the feedback changes their next debugging step, and how.

ASM-05 — Helpful hints without removing the challenge

Assumption: Hints can support learning without removing the useful challenge.

  • Status: Open
  • Validation: Test staged hints with learners during Week 2.
  • Observe: Whether learners continue investigating or use a hint as the answer.

ASM-06 — Control over guidance

Assumption: Learners want control over when guidance appears.

  • Status: Open
  • Validation: Compare optional guidance with automatic guidance.
  • Observe: Which moments learners find helpful or disruptive, and which guidance mode they prefer.

ASM-07 — Friction during setup

Assumption: Setup friction prevents some learners from starting debugging practice.

  • Status: Open
  • Validation: Observe learners starting their first task during Week 2.
  • Observe: Which setup steps require help and where learners abandon the flow.

ASM-08 — Progressive access to tools

Assumption: Learners prefer progressive tool access over completing the full environment setup before starting.

  • Status: Open
  • Validation: Compare progressive onboarding with full environment setup.
  • Observe: Which flow learners can start without assistance.
