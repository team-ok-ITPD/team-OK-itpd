# ADR-002: Represent Each Exercise With Buggy Code, Reference Code, And pytest Tests

- **Status:** Accepted
- **Date:** 2026-10-24
- **Decision makers:** Debug GYM team
- **Requirements:** [FR-003](../../functional-requirements/fr/FR-003.md), [FR-004](../../functional-requirements/fr/FR-004.md), [QR-01](../../quality-requirements/qr/QR-01.md), [QR-03](../../quality-requirements/qr/QR-03.md), [QR-05](../../quality-requirements/qr/QR-05.md)
- **Quality attributes:** [QR-01: Functional Suitability / Functional Correctness](../../quality-requirements/qr/QR-01.md), [QR-03: Maintainability / Testability](../../quality-requirements/qr/QR-03.md), [QR-05: Reliability / Recoverability](../../quality-requirements/qr/QR-05.md)

## Context

An exercise needs executable evidence that its intended defect exists and that the reference fix removes it. [DEC-006](../../decisions.md#dec-006) chose a correct program, a buggy program, and pytest tests, while [DEC-010](../../decisions.md#dec-010) requires complete test output for the learner.

## Decision Drivers

- [FR-003](../../functional-requirements/fr/FR-003.md) requires deterministic reproduction of the intended defect.
- [FR-004](../../functional-requirements/fr/FR-004.md) requires the same tests to distinguish buggy and corrected behavior.
- [QR-01](../../quality-requirements/qr/QR-01.md) defines the measurable bug-and-test contract.
- [QR-03](../../quality-requirements/qr/QR-03.md) requires automated checks of the exercise and reference implementation.
- [QR-05](../../quality-requirements/qr/QR-05.md) requires reset state to reproduce the original failures.

## Considered Options

- Maintain buggy code, release-side reference code, and pytest tests for each exercise.
- Generate expected input and output comparisons with an AI service.
- Ship buggy code and assess learner fixes manually.
- Ship tests without a maintained reference implementation.

## Decision

Represent every authored exercise with learner-facing buggy code, release-side reference code, and pytest tests. The tests must fail for the intended reason against the buggy code and pass against the reference code. Each exercise provides a deterministic reproduction command and displays its complete test output. The reference code is release evidence and is not copied into the learner workspace. The current public repository does not make that reference code secret.

## Consequences

### Positive

- Authors and CI can verify both sides of the exercise contract automatically.
- Learners use the same command to reproduce a defect and verify their fix.
- The reference implementation makes accidental impossible or already-correct exercises detectable.

### Negative

- Authors must maintain three coordinated artifacts for each exercise.
- Passing tests establish the encoded behavior, not every possible correct implementation property.
- Reference code needs an access-control boundary if future exercises require it to be hidden rather than merely excluded from the workspace.

## Rejected Alternatives

### AI-Generated Input And Output Comparisons

Generated comparisons are less repeatable than repository-owned tests and do not provide the executable contract required by QR-01.

### Manual Assessment Of Fixes

Manual assessment cannot provide immediate, repeatable verification and does not satisfy the clean-checkout checks in QR-03.

### Tests Without A Reference Implementation

Tests alone show that buggy code fails but cannot prove that the intended corrected behavior passes the same contract.
