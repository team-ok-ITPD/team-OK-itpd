# ADR-002: Validate Exercises With A Buggy Program And An Oracle

- **Status:** Accepted
- **Created:** 2026-10-24
- **Updated:** 2026-10-24
- **Containers:** `debug workspace`, `workspace store`
- **Addresses:** [`FR-003`](../../functional-requirements/fr/FR-003.md), [`FR-004`](../../functional-requirements/fr/FR-004.md), [`QR-01`](../../quality-requirements/qr/QR-01.md), [`QR-03`](../../quality-requirements/qr/QR-03.md)
- **Decision:** [`DEC-006`](../../decisions.md#dec-006), [`DEC-010`](../../decisions.md#dec-010)

## Context

An exercise needs executable evidence that its intended defect exists and that a correct implementation passes the same tests. The Customer requested correct code, buggy code and executable tests, with complete test output. The repository already implements this contract for one prepared exercise.

## Considered Options

- **Buggy code, reference code and pytest tests:** chosen because two implementations provide repeatable evidence about the same expected behavior.
- **AI-produced JSON expectations alone:** rejected as the sole contract because generated expectations do not independently establish both correct and buggy behavior.
- **Compare the learner's source text with the reference:** rejected because different implementations can satisfy the same behavior.
- **Manual assessment only:** rejected for the practice loop because the learner needs immediate, repeatable feedback.

## Decision Outcome

Maintain learner-facing buggy code and tests in `exercise/`, and the author's reference implementation in `exercise_author/`. Product checks run the buggy exercise and run the same tests against a temporary reference copy; they must not replace a live learner's files.

The learner verifies code inside VS Code and inspects complete terminal output. Reference code is excluded from the workspace image but remains public in the repository. These checks provide self-practice feedback, not a recorded submission, attempt or trusted grade.

## Consequences

- **Functional Suitability / Functional Correctness**, covered by [QR-01](../../quality-requirements/qr/QR-01.md): both implementations can be checked, but author review is still needed to identify the intended defect.
- **Maintainability / Testability**, covered by [QR-03](../../quality-requirements/qr/QR-03.md): the exercise contract is executable from a clean checkout; authors must keep code and tests coordinated.
- Passing editable local tests is not proof against tampering or correctness outside the encoded cases. Independent assessment requires an agreed requirement and separate implementation.
