# ADR-001: Package The Catalog And VS Code Workspace Locally

- **Status:** Accepted
- **Created:** 2026-10-24
- **Updated:** 2026-10-24
- **Containers:** `exercise catalog`, `debug workspace`, `workspace store`
- **Addresses:** [`FR-001`](../../functional-requirements/fr/FR-001.md), [`FR-002`](../../functional-requirements/fr/FR-002.md), [`FR-003`](../../functional-requirements/fr/FR-003.md), [`FR-004`](../../functional-requirements/fr/FR-004.md), [`FR-005`](../../functional-requirements/fr/FR-005.md), [`FR-006`](../../functional-requirements/fr/FR-006.md), [`FR-007`](../../functional-requirements/fr/FR-007.md), [`QR-03`](../../quality-requirements/qr/QR-03.md), [`QR-04`](../../quality-requirements/qr/QR-04.md)

## Context

The first product connects exercise discovery to a prepared Python investigation environment. The implemented stack was recorded in [DEC-005](../../decisions.md#dec-005), and the Customer requires real VS Code debugging in [DEC-007](../../decisions.md#dec-007). This record documents existing packaging and ownership choices, not approval of browser access in place of SSH.

## Considered Options

- **Local Docker with code-server, Python and pytest:** chosen to reuse the implemented environment and executable exercise checks.
- **A custom web editor:** rejected for the first slice because the team would need to supply real debugging and multi-file tooling separately.
- **Install the full toolchain directly on every learner's host:** rejected as the default because it transfers environment preparation to each learner.
- **A hosted workspace service:** deferred until provider selection, shared execution and access policy are settled.

## Decision Outcome

Use one learner-local Docker Compose service containing two C4 applications and a named-volume store:

- `exercise catalog` is the Python HTTP application and its static frontend; it owns prepared-exercise metadata, request matching and readiness checks.
- `debug workspace` is code-server with Python, pytest and debugpy; it owns the editor, terminal and debugger processes.
- `workspace store` owns persistent exercise files and editor configuration.

C4 containers are applications and stores, not Docker service count. The catalog links to VS Code; it does not grade a submitted solution. Future category browsing belongs to the catalog and assistance belongs to the workspace, without selecting an AI provider here.

## Consequences

- **Maintainability / Testability**, covered by [QR-03](../../quality-requirements/qr/QR-03.md): Python checks can exercise the catalog and exercise contract, but frontend behavior still needs separate verification.
- **Performance Efficiency / Time Behaviour**, covered by [QR-04](../../quality-requirements/qr/QR-04.md): discovery reuses a running workspace, but image downloads and editor startup must be measured rather than inferred from a health response.
- The single image couples catalog and workspace releases; this is a first-slice trade-off, not a requirement for future hosting.
- Genuine browser debugging does not satisfy FR-005's SSH and invalid-access criteria; they remain active until implemented or changed through a Customer decision.
