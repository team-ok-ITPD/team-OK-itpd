# ADR-005: Export Catalog Request Signals To An External Observability Backend

- **Status:** Proposed
- **Created:** 2026-11-08
- **Updated:** 2026-11-08
- **Containers:** `exercise catalog`
- **Addresses:** [`FR-013`](../../functional-requirements/fr/FR-013.md), [`QR-04`](../../quality-requirements/qr/QR-04.md), [`QR-06`](../../quality-requirements/qr/QR-06.md)

## Context

An operator who is told that searches are slow or failing needs to find the failed request and read its latency without attaching a debugger to a deployed service. The [observability plan](../../observability.md) defines [SLI-01](../../observability.md#sli-01) for the catalog search and the log line that identifies one request. The catalog already emits a request-duration histogram and a structured log line, and [QR-06](../../quality-requirements/qr/QR-06.md) requires that an operator can diagnose a failed request in staging within minutes.

## Considered Options

- Read the application's standard output on the VM: rejected because it gives no aggregate series and depends on shell access to the host.
- Add the metric and the log to the product's own database and dashboard: rejected because it adds load to the database that serves learners and makes the team build a monitoring tool.
- Export a metric and a structured log from the catalog to an external, self-hosted observability backend with one organization per environment: chosen.

## Decision Outcome

The `exercise catalog` exposes a Prometheus-format histogram behind a bearer token and writes one JSON log line per search request. The team's scraper and log collector send both to an observability backend that the team self-hosts and does not build, with a separate organization and token for staging and production. The backend is outside the product boundary and the product works with it absent. The metric and the log are implemented for the search route; the backend deployment and the staging check are not yet done.

## Consequences

- The operator can find one request by its `request_id` and read the failure series, supporting [QR-06](../../quality-requirements/qr/QR-06.md).
- Request handling adds a timer and one log write, which must stay small so the two-second search target in [QR-04](../../quality-requirements/qr/QR-04.md) holds.
- The team operates one more service per environment and keeps its addresses and credentials out of the repository.
- Request IDs stay in the log and out of metric labels, so the metric's label set stays bounded.
