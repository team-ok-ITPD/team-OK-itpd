# ADR-003: Keep The Prototype Learner-Local With Persistent State

- **Status:** Accepted
- **Created:** 2026-10-24
- **Updated:** 2026-10-24
- **Containers:** `exercise catalog`, `debug workspace`, `workspace store`
- **Addresses:** [`FR-002`](../../functional-requirements/fr/FR-002.md), [`FR-005`](../../functional-requirements/fr/FR-005.md), [`QR-02`](../../quality-requirements/qr/QR-02.md), [`QR-05`](../../quality-requirements/qr/QR-05.md)

## Context

Compose binds both ports to loopback, disables code-server authentication and stores one learner's files in a named volume. The Customer has not chosen a shared-hosting or authentication model. [RISK-03](../../risks.md#risk-03) names learner-local execution as the contingency until shared-service isolation is validated.

## Considered Options

- **Learner-local execution with a named volume:** chosen for the existing prototype to preserve edits across restarts.
- **One shared unauthenticated workspace:** rejected because it provides no ownership boundary between learners.
- **Execute learner code directly on a shared host:** rejected because editable code would share infrastructure without validated containment.
- **Authenticated, provisioned per-learner workspaces:** retained as a future option; routing, resource enforcement and access policy require a separate decision and evidence before a shared pilot.

## Decision Outcome

Keep the current prototype on the learner's own machine with loopback-only ports and persistent files in `workspace store`. Do not expose this unauthenticated deployment as a shared or public service.

Stopping or recreating the service preserves edits. Reset deliberately removes only the selected Compose project's exercise volume and recreates the original exercise; users must save anything they need first. An image update does not migrate files already held in a volume.

This documents operation already in force, not Customer acceptance of browser access instead of SSH. FR-005 remains unsatisfied. Shared deployment must first demonstrate QR-02 and introduce an agreed admission and isolation design.

## Consequences

- **Security / Resistance**, covered by [QR-02](../../quality-requirements/qr/QR-02.md): local operation avoids offering an unvalidated shared service, but does not demonstrate five-workspace isolation or bound hostile code on the learner's machine.
- **Reliability / Recoverability**, covered by [QR-05](../../quality-requirements/qr/QR-05.md): the volume preserves work and gives reset a defined boundary, but reset deletes edits and old volumes can retain stale exercise configuration.
- Authentication, SSH, per-learner provisioning and resource limits are not supplied by this decision and must not be inferred from a successful local demonstration.
