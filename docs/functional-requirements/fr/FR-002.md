# FR-002: Open A Ready Workspace

- **Status:** Active
- **Traces to:** [`US-02`](https://github.com/team-ok-ITPD/team-OK-itpd/issues/29), [`DEC-005`](../../decisions.md#dec-005), [`CON-02`](../../product-vision.md#con-02), [`ADR-001`](../../architecture/adr/ADR-001.md), [`ADR-003`](../../architecture/adr/ADR-003.md)
- **Containers:** `exercise catalog`, `debug workspace`

## Behavior

When a matching exercise is requested and its workspace is healthy, the product shall provide a workspace containing the broken code, its dependencies, its tests, and its debugger configuration without requiring the learner to install language tooling.

When workspace preparation fails, the product shall report the failure and shall leave no partial environment linked to the learner.

## Acceptance Criteria

### AC-01

Given a healthy workspace, when a supported exercise is requested, then opening the returned link shows `remove_negatives.py`, its pytest tests, and the `Debug reproduction tests` launch configuration.

### AC-02

Given a workspace health endpoint that returns `503`, when a supported exercise is requested, then the catalog returns `503`, explains that the workspace is unavailable, returns no exercise object, and associates no partial environment with the learner.

### AC-03

Given preparation has allocated an incomplete learner environment and then fails, when the failure is reported, then the failed environment is removed and cannot be opened or reused by the learner.

The baseline reuses a prestarted local workspace and reports its unavailability. It does not implement per-user provisioning or cleanup; returning no link is not proof of provisioning cleanup. The ready-environment requirement does not decide the still-open hosting model.
