# FR-011: Verify A Submission In A Fresh Container

- **Status:** Active
- **Traces to:** [`DEC-037`](../../decisions.md#dec-037), [`ADR-002`](../../architecture/adr/ADR-002.md), [`ADR-004`](../../architecture/adr/ADR-004.md), [`QR-02`](../../quality-requirements/qr/QR-02.md)
- **Containers:** `exercise catalog`

## Behavior

When a learner submits a solution, the product shall run the exercise's tests on the submitted code in a fresh container and record the pass counts that run produced. It shall not trust counts reported by the browser or the VS Code extension.

The verification container shall have no network access, bounded memory, CPU, process count and run time, and shall be removed after the run.

When more verifications are requested than the configured concurrency and waiting queue allow, the product shall refuse the extra request with a busy message.

## Acceptance Criteria

### AC-01

Given a submission whose client claims all tests pass, when the submission is verified, then the stored counts equal the container's test results.

### AC-02

Given the configured concurrency and queue are full, when another submission arrives, then it is refused as busy and no container starts.

### AC-03

Given a completed verification, then no container for that run remains.
