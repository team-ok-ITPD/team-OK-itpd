# FR-013: Expose The Quality Signal Of The Catalog Search

- **Status:** Active
- **Traces to:** [`QR-04`](../../quality-requirements/qr/QR-04.md), [`QR-06`](../../quality-requirements/qr/QR-06.md), [`ADR-005`](../../architecture/adr/ADR-005.md)
- **Containers:** `exercise catalog`

## Behavior

When the catalog handles a request to search the prepared exercises, the product shall expose the quality signal named by [SLI-01](../../observability.md#sli-01) to the observability backend of its environment: a request-duration histogram with the labels `route` and `outcome`.

The product shall also write one structured log line for that request with `request_id`, `route`, `outcome`, `status` and `duration_ms`, and shall return the same `request_id` in the `X-Request-ID` response header, so one failed request can be found in the log.

The signal shall carry no query text, user identifier, header or request body. The metrics endpoint shall answer only a request that carries the environment's token.

When no observability backend is configured, the product shall serve the request as it otherwise would.

## Acceptance Criteria

### AC-01

Given a search request that fails with a 404, when it completes, then the response carries an `X-Request-ID` header and the log holds one `catalog_request` line with that `request_id`, `route`, `outcome` `client_error` and its `status` and `duration_ms`.

### AC-02

Given recorded search requests, when the metrics endpoint is read with the environment's token, then the histogram `debug_gym_http_request_duration_seconds` reports the requests grouped by `route` and `outcome`.

### AC-03

Given a request to the metrics endpoint without the token or with a wrong one, then the product answers 404.

### AC-04

Given any search request, then neither the log line nor the metric carries the query text, a user identifier, a header or the request body.

## Open points

Only `POST /api/exercises` is instrumented. The signal does not yet carry an environment label; each environment sends to its own observability organization instead. No staging or production deployment has been checked against this behavior.
