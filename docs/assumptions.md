# Assumptions

## ASM-01

Learners want debugging practice that feels like working in an existing codebase.

- **Status:** Open
- **How to check:** ask learners to compare a snippet task with a small
  multi-file task in Week 2 and explain which better supports their goals.

## ASM-02

Repository-level debugging tasks can be made approachable for learners.

- **Status:** Open
- **How to check:** observe learners starting and completing a small
  repository-level task in Week 2, recording where they need help or stop.

## ASM-03

Repository-level debugging practice offers value that existing kata do not.

- **Status:** Open
- **How to check:** ask learners in Week 2 to compare the value of a Debug GYM
  repository task with a kata they have used before.

## ASM-04

Learners value feedback on how they investigate a bug.

- **Status:** Open
- **How to check:** show learners investigation feedback in a Week 2 prototype
  and ask what, if anything, it changes in their next debugging step.

## ASM-05

Hints can support learning without removing the useful challenge.

- **Status:** Open
- **How to check:** test staged hints in Week 2 and observe whether learners
  continue investigating or use a hint as the answer.

## ASM-06

Learners want control over when guidance appears.

- **Status:** Open
- **How to check:** test optional and automatic guidance in Week 2 and ask
  learners which moments helped or interrupted their investigation.

## ASM-07

Setup friction prevents some learners from starting debugging practice.

- **Status:** Open
- **How to check:** observe learners starting a first task in Week 2 and record
  every setup step where they need help or abandon the flow.

## ASM-08

Learners prefer progressive tool access to full environment setup before starting.

- **Status:** Open
- **How to check:** compare a progressive onboarding flow with full environment
  setup in Week 2 and record which one learners can start without assistance.
