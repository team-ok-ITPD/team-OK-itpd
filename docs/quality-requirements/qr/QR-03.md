# QR-03: The Product Checks Run From A Clean Checkout

A developer can run the product's checks from a clean checkout with one documented command, and a broken change to a critical module makes them fail.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium
- **Changed:** 2026-10-31: expanded the critical modules after the Django application and VS Code submission extension became part of the product in [PR #103](https://github.com/team-ok-ITPD/team-OK-itpd/pull/103).

## Scenario

### Source

A team member, or the continuous integration run, with a fresh clone of the repository.

### Stimulus

The member installs the pinned dependencies and runs the documented check command after changing a critical module.

### Environment

A clean checkout with the dependencies of `requirements.lock` installed and no other local setup, on the Python version the product container uses.

### Artifact

The critical modules are the catalog backend `app/server.py`, the exercise and
reference solution in `exercise/remove_negatives.py` and
`exercise_author/correct_remove_negatives.py`, the Django endpoint and workspace
layers in `app/adel_b/bugs/views.py` and `app/adel_b/bugs/workspaces.py`, account
handling in `app/adel_b/accounts/views.py`, and the VS Code result parser in
`app/adel_b/vscode-extension/junit.js`.

### Response

The checks shall run to the end without further setup, report which module failed, and fail when a critical module's behavior is broken.

### Response Measure

The product workflow runs to completion from a clean checkout, with at least one
automated test for every named critical module, and a deliberate
behavior-breaking change in any named module makes its automated-test step fail.

## QRT-01

The product's automated suites run from a clean checkout and cover every critical module named by this requirement.

- **Status:** Active
- **Level:** CI
- **Runs at:** the `test` job's three `Automated tests` steps in `.github/workflows/product.yml`, on every pull request and on `main`.

### Procedure

1. From a clean checkout, let the product workflow install the pinned Python dependencies.
2. Run the catalog and exercise contract, Django application and VS Code extension automated-test steps.
3. Read the three step results and their test reports.

**Pass when:** all three automated-test steps pass and their suites contain at least one test for every critical module named by QR-03.

### Result

**Passes, 2026-10-31.** The catalog and exercise contract, Django application
and VS Code extension steps passed from the merged `main` commit `fabc022` in
[Product checks run 41228949546](https://github.com/team-ok-ITPD/team-OK-itpd/actions/runs/41228949546).
