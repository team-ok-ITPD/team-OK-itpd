# Week 3 AI usage

## Tools

### OpenCode

OpenCode was used to inspect the repository and Assignment 3 requirements,
identify missing deliverables, draft planning and workflow documentation, build
the first product slice, add automated tests, configure GitHub resources, and
prepare release and reporting artifacts.

The team reviewed the generated changes through pull requests. Suggested code
was adapted to the repository's existing conventions and checked with product
tests, Docker container smoke tests, Markdown linting, and link checking. Claims
that required Customer evidence were not treated as facts; unresolved customer
acceptance was recorded as a deviation instead.

### Codex

Codex was used by the team to inspect the MUP against its story acceptance
criteria and draft the initial verification record. The team separated those
source-level findings from later manual checks and manually verified Docker
startup, the exercise failure and fix, workspace reset, and browser debugging.

Codex output was retained where it matched observed evidence. Findings that
could not be demonstrated, including SSH access, authentication, and Customer
acceptance of the running application, remained explicitly unresolved.
