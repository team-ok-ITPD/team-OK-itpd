# Kickoff Meeting Script

`[OPEN]` and `[CLOSED]` label question format: open-ended prompts invite discussion, while closed prompts can be answered briefly (often yes or no). Record the actual answers and discussion in the meeting report after the meeting.

## 1. Learners and problem

- [OPEN] Who is the primary learner we want Debug GYM to support, and what debugging situations are hardest for them?
- [CLOSED] Is improving debugging skill, rather than only completing coding exercises, a goal we want to prioritize?

## 2. Task realism

- [OPEN] What makes a debugging task feel realistic to the intended learner?
- [CLOSED] Should we investigate tasks that use existing code rather than only greenfield exercises?

## 3. Investigation tools and feedback

- [OPEN] Which tools or observations would help a learner investigate without solving the task for them?
- [CLOSED] Should learners be able to request hints instead of receiving them automatically?

## 4. AI and learner agency

- [OPEN] What role, if any, should AI play during a debugging exercise?
- [CLOSED] Should a learner be able to complete a task without using AI assistance?

## 5. Scope, onboarding, and success

- [OPEN] What is the smallest useful first version of Debug GYM, and what should it leave out?
- [CLOSED] Is reducing setup friction important enough to influence the first-task experience?
